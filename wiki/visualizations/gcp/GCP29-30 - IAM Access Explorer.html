Each permission reads service.resource.verb. You can't grant one permission directly. You grant a role that contains it.

    What each role can do with networking resources

    ✔ create, modify and delete · R read-only · — none. Based on the lecture and the Compute Engine IAM role reference, simplified to the networking resources in this course.

    Network ViewerRead-only on everything in networking. Good for auditors, dashboards and config-scanning tools running as a service account.roles/compute.networkViewer
    Network AdminBuilds the network: VPCs, subnets, routes, NAT, VPN, load balancers. Firewall rules and SSL certificates are read-only.roles/compute.networkAdmin
    Security AdminManages firewall rules and SSL certificates. The split from Network Admin is deliberate: the team that builds the network isn't automatically the team that opens it.roles/compute.securityAdmin

    Pick only the permissions the job needs

    The lecture's example: create, modify and delete firewall rules, but read-only SSL certificates. Security Admin gives too much, and Network Admin gives too little.
