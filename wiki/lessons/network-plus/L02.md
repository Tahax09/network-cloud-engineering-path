# L02 — Networking Appliances & Applications

## Summary
Every OSI concept now gets a real device attached to it. This lesson covers what each appliance does, its OSI layer, and how to place it correctly in a network diagram. These are the exact devices running in AWS VPCs, enterprise data centers, and your k3s cluster.

## Device Map by OSI Layer

```
L7 (Application)  → NGFW, IDS/IPS, Proxy, Load Balancer, CDN
L4 (Transport)    → Stateful Firewall, Load Balancer
L3 (Network)      → Router, Layer 3 Switch
L2 (Data Link)    → Layer 2 Switch (CAM table)
L1 (Physical)     → Hub, Repeater, Access Point
```

## Core Concepts

### Router — L3, Destination IP
The postal sorting center — reads the destination city (IP address) and picks the right truck (interface). Doesn't care about source; only cares about destination.

- Connects separate IP networks; each interface = a different network/gateway
- Maintains a **routing table** (connected, learned via protocols, default route)
- **Default route (0.0.0.0/0):** If no specific match, send here → to ISP/internet
- Frame arrives → router strips L2 frame → reads L3 IP → re-frames for next hop

**AWS equivalent:** Internet Gateway + Route Table in a VPC. `0.0.0.0/0 → igw-xxxx` = default route.

### Layer 2 Switch — L2, Destination MAC
The smart receptionist who memorizes which desk (port) every employee (MAC) sits at.

- Builds a **CAM table** (MAC → port mapping) by passively watching source MACs
- Unknown destination MAC → **floods** out all ports except the incoming one
- No IP needed to function (IP is for management only)
- **vs Hub:** Hub broadcasts everything to all ports. Switch learns and sends only to the right port.

### Layer 3 Switch — L2 + L3 Combined
- Ports can be switch ports (L2, MAC-based) or routed ports (L3, IP-based)
- Creates **SVIs** (Switched Virtual Interfaces) — logical L3 interfaces per VLAN
- Routes between VLANs without an external router; used in enterprise campus cores

### Firewall — Traffic Filter

| Generation | Layer | Behavior |
|-----------|-------|----------|
| Packet Filter | L3/L4 | Block/allow by IP + port; stateless |
| Stateful | L4 | Tracks TCP state; auto-allows return traffic |
| NGFW | L7 | Deep Packet Inspection; app-aware; integrated IPS |

**Stateful key insight:** Allows outbound HTTP → return traffic automatically allowed. No manual inbound rule needed for established sessions.

**AWS equivalent:** Security Groups (stateful, per-instance) and Network ACLs (stateless, per-subnet).

### IDS vs IPS

| | IDS | IPS |
|-|-----|-----|
| Full Name | Intrusion Detection System | Intrusion Prevention System |
| Action | Alert only | Block + alert |
| Position | Out-of-band (copy of traffic) | Inline (traffic passes through) |
| Risk | Missing an attack | Blocking legitimate traffic |
| Analogy | Security camera | Security guard at the door |

**Detection methods:** Signature-based (known patterns), Anomaly-based (deviations from normal), Behavior-based (what traffic does, not what it looks like).

### Load Balancer — Traffic Distribution

**Algorithms:**
| Algorithm | Behavior |
|-----------|----------|
| Round Robin | Rotate evenly across all servers |
| Weighted Round Robin | Higher-capacity servers get more traffic |
| Least Connections | Send to server with fewest active sessions |
| IP Hash | Same source IP always → same server (sticky) |

**SSL Offloading:** LB handles TLS encryption/decryption; backend servers get plaintext.
**Sticky Sessions:** Same user always routed to same backend (needed when sessions aren't shared).

**AWS equivalents:**
- ALB (Application LB) = Layer 7, routes by URL path/hostname
- NLB (Network LB) = Layer 4, ultra-high performance TCP/UDP
- GLB (Gateway LB) = Layer 3, used for inline security appliances

### Proxy Server — The Middleman

| | Forward Proxy | Reverse Proxy |
|-|--------------|---------------|
| Direction | Client → Internet | Internet → Servers |
| Hides | Client identity | Server identity |
| Use | Content filtering, caching | Load balancing, SSL termination, WAF |
| Analogy | Going OUT through a proxy | Traffic comes IN through a proxy |

**In k3s:** Your NGINX Ingress Controller is a **reverse proxy**. Sits at cluster edge, routes external traffic to internal services based on rules.

### CDN — Content Delivery Network
Geographically distributed edge nodes serve cached content from the nearest location.
- Reduces load on origin servers
- Provides redundancy
- **AWS:** Amazon CloudFront

### VPN Types

| Type | Use Case | Protocol |
|------|----------|----------|
| Remote Access | Employee → Corporate | SSL/TLS, IPsec |
| Site-to-Site | Branch ↔ HQ | IPsec |
| MPLS | WAN (ISP-managed) | MPLS |

**Exam trap:** MPLS VPNs provide logical separation but NOT necessarily encryption.

### QoS — Quality of Service
Three enemies of real-time traffic:
- **Delay:** Total end-to-end transit time
- **Jitter:** Variability in packet arrival timing → kills VoIP/video
- **Loss:** Dropped packets; TCP retransmits (delay), UDP = lost forever

QoS flow: Classify → Mark → Queue → Forward with priority
VoIP gets **Expedited Forwarding (EF)** — highest priority queue.

### TTL — Time To Live
- Field in IP header (L3); decremented by 1 at every router hop
- Packet dropped when TTL hits 0; router sends ICMP "Time Exceeded" back to source
- Defaults: Windows=128, Linux=64, Cisco=255
- **traceroute** exploits TTL: sends TTL=1, TTL=2, TTL=3... each expiry reveals a hop

```bash
traceroute google.com   # maps the route hop by hop via TTL expiry
```

### NAS vs SAN

| | NAS | SAN |
|-|-----|-----|
| Access | File-level (NFS, SMB) | Block-level |
| Network | Regular IP network | Dedicated fabric (Fiber Channel) |
| Complexity | Simple | Complex, enterprise |
| Use | Home/SMB | Data centers, databases |

## Key Terms

| Term | Definition |
|------|------------|
| Routing Table | Router's database of networks and next hops |
| Default Route | 0.0.0.0/0 — catch-all, matches any destination |
| CAM Table | Content Addressable Memory — switch MAC-to-port map |
| SVI | Switched Virtual Interface — L3 interface on switch per VLAN |
| Stateful Firewall | Tracks TCP state; auto-allows return traffic |
| NGFW | Next-Gen Firewall — DPI, app-aware, integrated IPS |
| SSL Offloading | Load balancer handles TLS so backends don't have to |
| Sticky Sessions | Same client always goes to same backend server |
| Forward Proxy | Acts for clients going outbound |
| Reverse Proxy | Acts for servers receiving inbound traffic |
| Jitter | Variability in packet arrival time |
| TTL | Time To Live — decremented per L3 hop; 0 = drop |

## Real-World Architecture

```
Internet → [Edge Router] → [NGFW] → [Load Balancer] → [Web1][Web2][Web3]
                                          ↓
                                    [L3 Switch] → [L2 Switch] → Servers/DBs
                                                              → [NAS/SAN]
```

**AWS equivalent:**
```
Internet Gateway → WAF/Shield → ALB → Target Group (EC2s) → RDS
     ↕ Route Tables    ↕ Security Groups    ↕ VPC Subnets
```

## Troubleshooting Scenario
> "Website is slow at peak hours. Sessions drop randomly."

1. Slow at peak → Check LB: all backends healthy? One overloaded? LB itself at capacity?
2. Sessions drop → Sticky sessions misconfigured? Sessions not shared across backends? Fix: enable persistence OR use centralized session store (Redis)
3. Fine overnight → Bandwidth contention at peak; check QoS marking
4. Still slow → CDN: is static content (JS, CSS, images) being cached? Every miss hits origin = slow

## Hands-On Practice
```bash
# Kubernetes load balancer / reverse proxy
kubectl get services -A
kubectl get ingress -A
kubectl describe ingress <name>

# TTL in action — each line = one router hop
traceroute 8.8.8.8

# Routing table — your k3s node is L3 routing for pods
ip route show

# ARP table — L2 to L3 mapping
arp -n

# Software firewall rules (iptables = your stateful firewall)
sudo iptables -L -n -v
```
