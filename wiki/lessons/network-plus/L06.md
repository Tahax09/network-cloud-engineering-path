# L06 — Network Topologies, Architectures & Traffic Flows

## Summary
Physical vs logical topology, enterprise three-tier vs data center spine-leaf, and north-south vs east-west traffic are all heavily tested. The SDN API directions (southbound/northbound) are a separate concept from traffic direction — don't confuse them.

## Physical vs Logical Topology
- **Physical:** How cables are actually run
- **Logical:** How traffic actually flows — determined by protocols and configuration (e.g., VLANs on the same switch creating logical isolation despite physical adjacency)

These are independent. Same physical switch, different VLANs → logical isolation.

## Topology Types

### Point-to-Point
Direct dedicated link between exactly two endpoints. No shared bandwidth. WAN connections, dedicated circuits between data centers. Cost scales linearly.

### Hub-and-Spoke (Star for WAN)
- LAN context: star — workstations to a central switch
- WAN/enterprise: hub-and-spoke — branches (spokes) connect to HQ (hub)

**Key rule:** Branch-to-branch traffic MUST traverse the hub. No direct spoke-to-spoke path. Intentional: all inter-branch traffic inspected at central firewall.

**Trade-off:** Higher latency for inter-branch traffic; hub is single point of failure.

### Full Mesh
Every node has a direct path to every other. Any-to-any without intermediary.
- Formula: **n(n-1)/2** connections for n nodes. 10 nodes = 45 connections.
- High redundancy + low latency, but expensive and complex at scale.

### Partial Mesh
Some direct connections, some routed. Practical compromise for critical links.

### Hybrid
Most real enterprise networks. Full/partial mesh between HQ, DC, and cloud (critical); hub-and-spoke between HQ and branches (low volume, centralized security).

### Wireless Mesh
APs relay wirelessly through each other. Dynamic rerouting. Used where wired backhaul to every AP is impractical.

## Three-Tier Architecture (Campus Networks)

```
[Core Layer]          ← High-speed backbone, L3, NO policy
      │
[Distribution Layer]  ← Inter-VLAN routing, QoS, ACLs, policy
      │
[Access Layer]        ← End devices, L2, PoE, VLAN assignment
```

| Tier | Also Called | Role |
|------|-------------|------|
| Access | Tier 1 | Connects workstations, phones, APs; L2 switching |
| Distribution | Tier 2, Aggregation, Workgroup | Inter-VLAN routing, QoS, ACLs; policy enforcement |
| Core | Tier 3 | Fast forwarding only; NO workstations, NO policy |

**Rule:** Never connect workstations directly to the core.

## Collapsed Core (Two-Tier)
Core + distribution merged into one powerful L3 switch. Access + Collapsed Core/Distribution. Dominant in mid-size networks. Lower cost, simpler management, less scalable.

## Spine-Leaf (Data Center)
Designed for east-west (server-to-server) traffic dominance.

```
[Spine][Spine]         ← Backbone; each spine connects to ALL leaves
   │  X  │
[L1][L2][L3][L4]      ← Access; each leaf connects to ALL spines
  |   |   |   |
 Srv Srv Srv Srv
```

**Iron rules:**
- Leaf → leaf: **prohibited** (must go through a spine)
- Spine → spine: **prohibited** (must go through a leaf)
- Max hops between any two endpoints: exactly **2** (leaf → spine → leaf)

Fixed two-hop path = predictable latency, easy capacity planning. Critical for microservice east-west traffic.

## Traffic Flows

### North-South
Traffic **crossing the perimeter** — entering or leaving the data center.
- Internet user → web server = north-south (both directions)
- Security controls sit at the perimeter: firewalls, WAF, load balancers

### East-West
Lateral traffic **within** the data center, between servers.
- Web server → app server → database = east-west
- Never crosses the perimeter
- Has exploded with microservices and containers
- **Most pod-to-pod traffic in Kubernetes is east-west**

**Exam trap:** Three-tier app communicating internally = east-west. Same web server responding to internet client = north-south.

### SDN API Directions (different meaning — don't confuse with above)
- **Southbound API:** SDN controller → network device (pushes forwarding rules). OpenFlow is the classic southbound protocol.
- **Northbound API:** Applications → SDN controller (request policy implementation)

## Troubleshooting Scenario
> Branch-to-branch file transfers are slow. Ping between branches shows 45ms, but branches are 8km apart.

Cause: Hub-and-spoke WAN. Branch traffic goes B1 → HQ (30km) → B2 (30km) = 60km round trip even though branches are 8km apart. The 45ms is correct for 60km fiber + HQ routing.

Options:
1. Direct point-to-point between branches (partial mesh) — eliminates hairpin
2. Site-to-site VPN directly between branches (logical direct path, cheaper)
3. Move latency-sensitive application to HQ

**Insight:** Hub-and-spoke optimizes for centralized security and administration, not inter-branch performance. Change the topology when inter-branch performance is a requirement.

## Real-World Connections
- **Your k3s cluster:** All pod-to-pod traffic is east-west. Kubeshark shows this clearly.
- **AWS VPC:** Traffic between subnets in the same VPC = east-west. Traffic from internet to EC2 = north-south.
- **Enterprise campus:** Distribution layer is where inter-VLAN routing happens — same function as k3s's CNI routing between pod CIDRs.
