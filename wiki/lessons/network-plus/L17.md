# L17 — Network Access and Management

## Summary
This lesson covers how remote access is secured (VPN technologies and types), how administrators access devices (console/SSH/GUI/API), and two architectural patterns for management traffic (jump box, in-band vs out-of-band). The exam tests: TLS VPN vs IPsec VPN, clientless vs client VPN, split vs full tunnel security implications, jump box purpose, and in-band vs out-of-band management.

---

## Core Concepts

### VPN Categories

**Site-to-Site VPN:**
- Connects two fixed locations (HQ → Branch) over the public internet
- Creates a persistent tunnel between routers/firewalls at each end
- Users at both sites don't need VPN client software — the gateway handles it transparently
- Typically uses **IPsec** for encryption
- Think of it as a logical private WAN link over a public medium

**Client-to-Site VPN (Remote Access VPN):**
- Individual device (laptop/phone) connects to the corporate network from anywhere
- Requires VPN client software on the endpoint (or is browser-based / clientless)
- Uses **TLS** (with client software) or a clientless portal
- Most common: employees working from home

**Personal VPN (Consumer VPN):**
- Service provider acts as a proxy — hides your traffic from your ISP / local network
- Obscures origin (privacy) rather than providing corporate access
- Examples: NordVPN, Mullvad, etc.

---

### VPN Security Properties

| Property | Mechanism | What It Protects |
|----------|-----------|-----------------|
| **Confidentiality** | Encryption | Prevents traffic interception/reading |
| **Integrity** | Hashing (HMAC) | Verifies data wasn't altered in transit |
| **Authentication** | Certificates, PSK, HMAC, username/password | Verifies both endpoints are who they claim to be |
| **Anti-replay** | Sequence numbers | Prevents captured packets from being retransmitted by an attacker |

Authentication methods by VPN type:
- Site-to-site: digital certificates or pre-shared keys (PSK)
- Client-to-site: username/password (most common), certificates, or MFA

---

### IPsec — Site-to-Site Protocol

**Two header types:**
| Header | Acronym | What It Provides |
|--------|---------|-----------------|
| Authentication Header | AH | Authentication + integrity only — NO encryption |
| Encapsulating Security Payload | ESP | Authentication + integrity + **encryption** |

In practice, ESP is almost always used — AH alone doesn't encrypt traffic.

**Two modes:**
| Mode | IP header | Use case |
|------|-----------|---------|
| **Tunnel mode** | Original IP headers encapsulated inside new outer headers | Site-to-site — hides internal IP addresses from the public internet |
| **Transport mode** | Original IP headers preserved (visible) | Host-to-host within a trusted network; no address hiding |

**Tunnel mode is the exam default for site-to-site VPNs.** The original packet is wrapped entirely inside the IPsec packet, so source/destination IPs from the private networks are hidden in transit.

---

### TLS VPN — Client-to-Site

**TLS (Transport Layer Security)** is the successor to SSL. Used in HTTPS, email, and VPNs.

**Two implementation styles:**

**Client-based TLS VPN:**
- Dedicated VPN software installed on the endpoint
- Can run any protocol (not just HTTP/S)
- Supports **full tunnel** or **split tunnel** mode

**Clientless TLS VPN (browser-based):**
- User navigates to a portal URL in a browser — no software to install
- Security gateway serves the VPN session over HTTPS
- Limited to web-compatible traffic (HTTP/S, browser apps)
- More restrictive than client-based but zero deployment overhead

**Exam trap:** Clientless VPN = browser-based = TLS = portal page. This is not the same as IPsec. If a question describes "employees access corporate apps via a browser without installing software," the answer is TLS VPN (clientless).

---

### Split Tunnel vs Full Tunnel

```
                   Full Tunnel                     Split Tunnel
                   ──────────                      ────────────
All traffic →      Corporate VPN gateway            Corporate traffic → VPN
                   (internet filtered by IT)        Everything else → direct internet

Security:          Higher (corp firewall            Lower (malware can enter via
                   sees all traffic)                internet bypass, then reach corp
                                                    resources through the VPN)

Bandwidth:         Higher on corp gateway           Lower on corp gateway
                   (must handle all client          (only corp-destined traffic
                   internet traffic)                traverses VPN)
```

**Security implication:** With split tunnel, a user could visit a malicious site, download malware, and that malware could then traverse the VPN connection back to corporate resources. The corporate firewall never sees the initial download. Full tunnel prevents this — all traffic routes through corporate inspection.

### Device Access / Connection Methods

| Method | Interface | Encryption | Access Type |
|--------|-----------|-----------|-------------|
| **Console** | Text CLI | None (direct physical) | Local physical only (console cable / hypervisor) |
| **SSH** | Text CLI | Yes (encrypted) | Network-based (needs IP address) |
| **GUI** | Graphical windowing | Depends (VNC/RDP can encrypt) | Local or remote |
| **Web UI** | Browser-based GUI | TLS (HTTPS) | Network-based |
| **API** | Code/HTTP requests | TLS (HTTPS recommended) | Network-based, programmatic |

**Console access:** You are physically at the device or connected via console port + terminal emulator (e.g., PuTTY in serial mode). No network IP required. Last resort when SSH is unavailable.

**SSH:** Encrypted, network-based text access. Port 22. Requires IP configured on the device. Standard for Linux/network device remote administration.

**GUI:** Full desktop environment (Windows/Linux). Less knowledge required but restricted to available GUI options; not all CLI commands have GUI equivalents.

**Web UI:** Browser-based management (common on consumer routers, Kubernetes dashboards, Kibana, Grafana). Subset of full CLI capability.

**API:** Code talks to device via HTTP/REST or NETCONF/RESTCONF. Enables automation and IaC. Device must expose and have API enabled.

### Jump Box (Bastion Host)

**Problem:** You need external access to internal devices, but directly exposing internal devices to the internet is a security risk.

**Solution:** A **jump box** (also called bastion host or jump server) is a hardened device that:
- Has a public-facing interface (accessible from the internet)
- Has access to internal/private network resources
- Is the **only** path from outside to internal devices

```
Internet → [Jump Box] → Internal switches, routers, servers
              ↑
          One hardened entry point — lock this down, log everything
```

**Security model:** You focus all your hardening, monitoring, MFA, and logging on the single jump box. Internal devices have no direct internet exposure. If you can't authenticate to the jump box, you can't reach anything else.

**In k3s:** This is exactly how you'd expose cluster administration securely — a bastion EC2/VM in a public subnet that SSHes into the private nodes. Nothing else in the cluster is publicly routable.

**AWS/GCP equivalents:** EC2 bastion host in a public subnet; GCP has a dedicated Cloud Identity-Aware Proxy (IAP) that replaces traditional jump boxes with identity-based tunneling.

### In-Band vs Out-of-Band Management

| | In-Band | Out-of-Band |
|-|---------|-------------|
| **Definition** | Management traffic shares the same network path as user data | Management traffic uses a separate dedicated path |
| **Risk** | Normal users share the network — management traffic more exposed | Management traffic isolated from user access |
| **Implementation** | Same interfaces, same VLANs | Separate management VLAN + management IP addresses (or dedicated physical network) |
| **Common approach** | Most small networks default to in-band | Enterprise: dedicated management VLAN (e.g., VLAN 99) with access only to admins |

**Out-of-band in practice:** Each device gets a **management IP** on a dedicated management VLAN. Admins reach it only from the management subnet (often via a jump box on the management VLAN). Normal user VLANs can't route to the management VLAN.

**Why it matters:** If a user VLAN is compromised, attackers can't reach device management interfaces — those are on a separate, isolated segment.

## Key Terms

| Term | Definition |
|------|-----------|
| Site-to-site VPN | Persistent encrypted tunnel between two fixed locations; gateways handle it transparently |
| Client-to-site VPN | Individual device connects to corporate network remotely; requires client software or browser |
| Personal VPN | Consumer privacy tool — proxies/obscures traffic from ISP or local network |
| IPsec | Encryption suite for site-to-site VPNs; uses AH (auth only) or ESP (auth + encryption) |
| AH (Authentication Header) | IPsec header providing authentication and integrity — no encryption |
| ESP (Encapsulating Security Payload) | IPsec header providing authentication, integrity, and encryption |
| Tunnel mode | IPsec wraps entire original packet — original IPs hidden; used for site-to-site |
| Transport mode | IPsec adds security to payload but preserves original IP headers |
| TLS VPN | Client-to-site VPN using TLS; can be client-based (any protocol) or clientless (browser only) |
| Clientless VPN | Browser-based VPN portal; no software install; limited to web traffic |
| Full tunnel | All VPN client traffic routes through the corporate gateway |
| Split tunnel | Only corporate-destined traffic routes through VPN; rest goes direct to internet |
| Console access | Physical/local text CLI access via console cable or hypervisor |
| SSH | Encrypted text-based remote access over network; port 22 |
| Jump box / Bastion host | Single hardened entry point from internet to internal resources |
| In-band management | Admin traffic shares same network path as user data |
| Out-of-band management | Admin traffic on dedicated separate VLAN/network, isolated from users |
| Anti-replay | VPN feature using sequence numbers to prevent retransmission attacks |
| PSK | Pre-shared key — shared secret for VPN authentication (site-to-site) |

## Real-World Connections

**k3s lab:** Your cluster's kubectl access is in-band management — it shares your home network. A production k3s or EKS cluster would put the API server on a private subnet with a jump box or VPN as the only entry point. That's the out-of-band pattern.

**AWS VPN:** AWS Site-to-Site VPN uses IPsec tunnel mode to your on-premises router. AWS Client VPN uses TLS. Both are real AWS products — the exam distinction maps directly to what AWS sells.

**WireGuard vs IPsec vs TLS VPN:** WireGuard is a newer lightweight VPN that doesn't fit neatly into the traditional IPsec/TLS split — worth knowing for interviews. CompTIA Network+ focuses on IPsec and TLS; WireGuard is post-exam-scope.

**5G/V2X relevance:** V2X sidelink uses direct device-to-device communication that bypasses the cellular network — in that sense, it sidesteps the VPN model entirely. The security model is handled at the Uu/PC5 interface layer, not at the VPN layer.

## Troubleshooting Scenario

**Scenario:** A remote employee reports that while connected to the corporate VPN, they can access internal systems fine, but internet browsing is very slow. After disconnecting from VPN, internet speed returns to normal.

**Analysis:** This is a **full tunnel** VPN configuration. All internet traffic is routing through the corporate gateway, which:
- Adds latency (traffic goes: employee → VPN → corporate → internet → corporate → employee)
- Saturates the corporate gateway with non-corporate internet traffic
- Slows perceived internet speed for the employee

**Solution options:**
- Switch to split tunnel (only corporate-range IPs go through VPN) — accepts the security tradeoff
- Upgrade corporate gateway bandwidth
- Implement SD-WAN to intelligently route traffic

**Note for exam:** The question may ask "what type of VPN causes all traffic to route through the corporate network?" — answer is full tunnel.

## Hands-On Ideas

1. **Jump box lab:** SSH to a cloud VM (AWS EC2 or GCP Compute), then from there SSH to a second VM that has no public IP. That chain is a jump box pattern — the first VM is your bastion.
2. **Out-of-band VLAN:** In your k3s environment, tag the node management interface on a separate VLAN and set an IP in a separate subnet. Access only from that VLAN. That's out-of-band management.
3. **Split vs full tunnel comparison:** If you have a VPN, test `traceroute 8.8.8.8` with VPN on vs off — if all hops change to route through corporate, it's full tunnel; if only corporate IPs change, it's split tunnel.
4. **Console port:** Connect to any network device via console cable + PuTTY/screen (9600 baud, 8N1 is the classic default). This is the baseline skill for any network engineer.

## Quiz

1. A company sets up a VPN between its HQ router and branch router over the internet. Both offices can communicate as if on the same LAN. What type of VPN is this?
   - A) Client-to-site  B) Personal VPN  C) Site-to-site  D) Clientless

2. A remote worker accesses internal web applications through a browser portal — no VPN software is installed. What is this?
   - A) IPsec tunnel mode  B) TLS VPN (clientless)  C) Full tunnel VPN  D) Out-of-band access

3. Which IPsec header provides both encryption AND authentication?
   - A) AH (Authentication Header)  B) ESP (Encapsulating Security Payload)  C) TLS  D) GRE

4. With split tunnel VPN enabled, a user downloads malware from a personal website. The malware then connects to internal corporate servers. Why was this possible?
   - A) The corporate firewall was not monitoring the VPN  
   - B) Split tunnel only routes corporate traffic through the VPN — internet traffic bypasses corporate inspection  
   - C) The VPN was not encrypting traffic  
   - D) The jump box was misconfigured

5. An administrator needs to manage a network device even if the primary production network is down. What management approach supports this?
   - A) In-band management  B) Full tunnel VPN  C) Out-of-band management  D) Clientless VPN

6. What is the primary security purpose of a jump box?
   - A) Encrypt all VPN traffic between sites  
   - B) Act as a single hardened entry point to internal resources, concentrating security monitoring  
   - C) Replace the need for out-of-band management  
   - D) Provide clientless VPN access to web applications

**Answers:** 1-C, 2-B, 3-B, 4-B, 5-C, 6-B
