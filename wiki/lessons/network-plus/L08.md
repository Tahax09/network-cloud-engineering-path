# L08 — Modern Networks

## Summary
SDN, VXLAN, Zero Trust, SASE, IaC tools, and IPv6 — the modern infrastructure layer. Know the three planes (management/control/data), the IaC tool matrix cold, and IPv6 address types. These concepts connect everything from L01–L07 into how production networks actually work today.

## SDN — Software-Defined Networking

### The Three Planes

| Plane | Role | Examples |
|-------|------|---------|
| Management | How you configure devices | SSH, SNMP, REST API |
| Control | How devices decide where to forward | OSPF, BGP, STP, CDP |
| Data (Forwarding) | Actual end-user traffic | Packets source→destination |

**Traditional networking:** Decentralized — each device independently runs control plane protocols and builds its own forwarding table.

**SDN:** Centralizes the control plane into a software controller. Devices receive forwarding rules via a southbound API (OpenFlow). No independent topology exchange.

### SDN Benefits
- **Zero-touch provisioning:** New device connects, automatically receives config from controller
- **Application awareness:** Route by application type, not just destination IP
- **Centralized policy:** Change once, propagates everywhere

**SD-WAN** = SDN applied to the WAN. Centrally managed, reduces control plane overhead, enables centralized branch provisioning.

### API Directions
- **Southbound API:** Controller → network device (pushes rules down). OpenFlow.
- **Northbound API:** Application → controller (requests policy).

## VXLAN — Virtual Extensible LAN
L2 network overlay on top of L3 IP infrastructure. Encapsulates Ethernet frames (L2) inside UDP packets (L3/L4). Receiving endpoint decapsulates and delivers original Ethernet frame.

**VNI (VXLAN Network Identifier):** 24-bit → supports ~16 million segments (vs 4,094 for 802.1Q VLANs).

Use cases: multi-site DC interconnect (VM migration without IP change), cloud L2 connectivity, multi-tenant environments.

- **Underlay:** Physical IP network
- **Overlay:** VXLAN logical network on top

**In k3s/Flannel:** Flannel often uses VXLAN as its overlay — pod packets are encapsulated in VXLAN UDP and sent across nodes. This is why pods can talk cross-node even though their IPs (10.42.x.x) are not physically routable on the host network.

## Zero Trust Architecture

**Traditional:** Hard perimeter; trust everything inside. Broken by cloud, remote work, BYOD.

**Zero Trust premise:** The network has already been breached. Every access request must be verified regardless of origin.

### Core Principles

| Principle | Implementation |
|-----------|---------------|
| Policy-based authentication | Evaluate: user, device health, time, location, app being accessed |
| Least privilege | JIT/JEA — minimum access for current task; tokens expire |
| Micro-segmentation | Internal zones; compromise of one ≠ access to others; limits blast radius |

Every user-application interaction becomes an explicit, auditable event.

## SASE — Secure Access Service Edge
Converges **SD-WAN** (connectivity) + **cloud security** (firewall, CASB, SWG, ZTNA) into one cloud service.

**Problem:** Remote users VPN to HQ → all traffic hairpins through HQ before reaching cloud apps. User → HQ → Office 365 → HQ → User. Extremely inefficient.

**SASE solution:** Security stack at cloud PoPs globally. Traffic inspected near the user, not at HQ.

| Component | Role |
|-----------|------|
| SD-WAN | Intelligent site routing |
| SWG | Web filtering, malware blocking |
| CASB | Cloud app access control |
| ZTNA | App-level access; replaces VPN |
| FWaaS | Cloud-delivered NGFW |

## Infrastructure as Code (IaC)

**Declarative:** Describe desired end state; tool figures out steps. Nothing happens if already in desired state.
**Imperative:** Describe specific steps. More like scripting. More control over order.

### IaC Tools — Exam Required

| Tool | File Name | Agent Model | Language |
|------|-----------|-------------|---------|
| **Ansible** | **Playbooks** | **Agentless** (SSH/API) | Python/YAML |
| **Chef** | **Cookbooks** | **Agent-based** | Ruby DSL |
| **Puppet** | **Manifests** | **Agent-based** | Puppet DSL |
| Salt | States | Both | Python |

**Agent-based (Chef, Puppet):** Software agent installed on every managed device. Polls server for updates. Continuously enforces state.
**Agentless (Ansible):** Connects via SSH/WinRM. No pre-installed software needed.

## IPv6 Addressing
128-bit (2¹²⁸ ≈ 3.4×10³⁸ addresses). Format: 8 groups of 4 hex digits, colon-separated.

**Compression rules:**
1. Drop leading zeros in a group: `0DB8` → `DB8`
2. Replace consecutive all-zero groups with `::` (only once per address)

Full: `2001:0DB8:0000:0000:0000:0000:0000:0001`
Compressed: `2001:DB8::1`

### IPv6 Address Types

| Type | Prefix | IPv4 Equivalent |
|------|--------|----------------|
| Global Unicast | 2000::/3 (starts with 2 or 3) | Public IP |
| Unique Local | FC00::/7 (FC or FD) | RFC 1918 private |
| Link Local | FE80::/10 (always FE80) | APIPA 169.254.x.x |
| Multicast | FF00::/8 (FF prefix) | Class D |
| Loopback | ::1 | 127.0.0.1 |

**Link Local (FE80::):** Auto-assigned on every IPv6 interface. Not routable. Every IPv6-capable interface gets one — why Windows shows FE80:: even in IPv4-only environments.

**Unique Local (FC00::/7):** Private IPv6 space. Valid within org, not internet-routed.

### IPv4→IPv6 Transition

| Method | How | When |
|--------|-----|------|
| Dual Stack | Both IPv4+IPv6 on same device | Preferred; modern default |
| Tunneling | Encapsulate one version inside the other | 6in4, Teredo, ISATAP |
| NAT64/NAT46 | Translate between versions at border | IPv6-only client → IPv4 server |

## Real-World Connections
- **Your k3s cluster:** Flannel CNI uses VXLAN overlay — pod-to-pod traffic crosses the VXLAN tunnel
- **AWS:** Uses SDN/NFV for VPC networking; all Security Groups and Route Tables are SDN in practice
- **Ansible:** The standard tool for automating k3s node configuration and network device management
- **Zero Trust:** Your Kubeshark + Elasticsearch observability stack is the monitoring layer Zero Trust needs

```bash
# See Flannel's VXLAN interface
ip addr show flannel.1
ip -d link show flannel.1   # shows VXLAN details (VNI, port)

# SDN in action — iptables rules pushed by kube-proxy (the controller)
sudo iptables -t nat -L KUBE-SERVICES -n

# IPv6 link local on your node
ip -6 addr show
```
