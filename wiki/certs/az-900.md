## Exam traps (consolidated)
| Pair | How to tell them apart |
|------|------------------------|
| Scalability vs elasticity | Scalability = *can* add capacity. Elasticity = happens *automatically* and shrinks back. |
| High availability vs reliability | Availability = uptime (SLA). Reliability = recovering from failure and continuing to work. |
| Vertical vs horizontal scaling | Up/down = resize one VM. Out/in = change the number of VMs. |
| Hybrid vs multi-cloud | Hybrid = public + private. Multi-cloud = two or more public providers. |
| CapEx vs OpEx | Cloud shifts spend from CapEx to OpEx. "No upfront cost" = OpEx / consumption-based. |
| Always customer-owned | Data, devices, accounts/identities, in every model including SaaS. |
| Composite SLA | Product of the individual SLAs, so lower than any single one. |
| Load Balancer vs Application Gateway | Layer 4 (TCP/UDP) vs layer 7 (HTTP, URL routing, WAF). |
| VPN Gateway vs ExpressRoute | Encrypted over the public internet vs private dedicated link. |
| RBAC vs Azure Policy | RBAC = what a *user* can do. Policy = what a *resource* is allowed to look like. |
| Resource Locks vs Policy | Locks block accidental delete/edit. Policy enforces compliance rules. |
| SQL Database vs SQL Managed Instance | New cloud app vs near-full SQL Server compatibility for migration. |
| Entra ID vs RBAC | Authentication (who are you) vs authorization (what can you do). |
| Storage redundancy | LRS one datacentre · ZRS across zones · GRS paired region · GZRS zones + paired region. |
